## 1. 仓库与分支

- **仓库:** `kingtiger202505/meicai-b2b2c-demo`（真基线）

## 3. 部署链路（CI）

- **触发:** 向 `001` 推送**且**改动命中路径过滤器时，运行 `.github/workflows/deploy.yml`；也可在 Actions 页手动 `workflow_dispatch`。
- **路径过滤器**（只有这些改动会触发部署）：`miniapp/**`、`apps/pos/**`、`apps/admin/**`、`packages/**`、`Dockerfile`、`Dockerfile.pos`、`Dockerfile.admin`、`docker-compose.yml`、`deploy/**`、`.github/workflows/deploy.yml`。
  - 因此 `docs/**` 等改动**不会**触发部署。
- **流程:** GitHub runner 通过 SSH 把源码 `rsync` 到测试机 → 远端 `docker compose up -d --build` 重建三个容器 → 开放宿主防火墙 8080/8081/8082 → 机器侧自检 + 外网冒烟校验（reachability + 产物内联校验）。
- **测试机:** `150.158.236.166`，`user=root`，Docker 单机；容器 `meicai-miniapp` / `meicai-pos` / `meicai-admin`，`restart: unless-stopped`，部署路径默认 `/opt/meicai-miniapp`。
- **部署 SSH key:** 公钥 `meicai-deploy@github-actions` 已加入测试机 `authorized_keys`，私钥存于 GH Secret（见下）。**复用这套，勿再另生成 key 或找店主要。**

### 前端构建期配置注入
构建期通过环境变量注入 Supabase 前端配置：miniapp 用 `TARO_APP_*`，POS/admin 用 `VITE_*`（同一个 Supabase 项目、同值）。POS/admin 的门店由登录后 `current_staff_store()` / `list_my_stores()` 解析，故不注入 `VITE_STORE_ID`。

### 所需 GitHub Secrets（仅名称）
| Secret 名 | 用途 |
|---|---|
| `DEPLOY_SSH_KEY` | 部署私钥（`meicai-deploy@github-actions`） |
| `DEPLOY_HOST` | 测试机地址 |
| `DEPLOY_USER` | 部署用户 |
| `DEPLOY_PORT` | SSH 端口（默认 22） |
| `DEPLOY_PATH` | 远端部署目录（默认 `/opt/meicai-miniapp`） |
| `SUPABASE_URL` | Supabase 项目 URL |
| `SUPABASE_ANON_KEY` | Supabase anon key（前端可用） |
| `STORE_ID` | miniapp 默认门店 ID |

1. **GitHub 推送权限。** 工作区 GitHub 连接是 `EronTo…/getdeployedai[bot]`，对 `kingtiger202505/meicai-b2b2c-demo` **只读**，每次部署推送撞 `403`，目前靠店主临时提供 PAT 救急。

   **根治:** 把 pooler 直连串 + DB 密码放入 GH Secret，在 CI 里用 `psql` 跑 migrations（service_role 不够，只能走 data-plane）——待永久推送权限打通后落地。

## 6. 手动部署 / 排障

- **手动触发部署:** GitHub → Actions → “Deploy …” → `Run workflow`（`workflow_dispatch`）。
- **机器侧重建:** SSH 到测试机部署目录，`docker compose up -d --build`。
- **查看容器/端口:** `docker compose ps`；`ss -tlnp | grep -E ':8080|:8081|:8082'`。
- **冒烟:** `curl -fsSI http://150.158.236.166:8080/`（POS `:8081` / admin `:8082`）。
