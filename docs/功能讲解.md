# 美菜 B2B2C 闭环系统 — 功能讲解文档

> 本文档面向非技术人员，按「业务闭环讲故事」的方式讲解系统功能。

---

## 一、先理解：什么是 B2B2C 闭环

这套系统连接了四个角色，形成一个完整的业务闭环：

```
顾客扫码点餐（小程序）
    ↓
餐厅 POS 收银（收钱、接单）
    ↓
后厨 KDS 出餐（做菜、叫号）
    ↓
库存自动扣减（BOM 配方算用料）
    ↓
库存预警 → 向美菜平台采购
    ↓
供应商报价 → 送货到店
```

**简单说**：顾客点了一道西红柿炒蛋，系统自动扣减"西红柿"和"鸡蛋"的库存；库存低于安全线时，自动提醒采购；采购下单后，供应商送货。整个过程从顾客下单到餐厅买菜，全链路打通。

---

## 二、角色一：消费者（顾客）— 微信小程序

顾客在餐厅里看到的就是这个小程序，核心体验是「自助点餐」。

### 1. 扫码绑定桌号

**场景**：顾客走进餐厅，坐下后想点餐。

**操作**：扫桌角的二维码，自动进入小程序并绑定桌号（如"3号桌"）。

**结果**：不用喊服务员，自己就能下单，订单会自动关联到桌号。

### 2. 浏览菜单 & 下单

**场景**：顾客想看看有什么菜，选几个想吃的。

**操作**：在菜单页浏览菜品分类（热菜、凉菜、酒水），点"+"加菜到购物车，确认后提交订单。

**结果**：订单提交到餐厅 POS 和后厨，顾客可以看到订单状态。

### 3. 微信支付 / 会员卡支付

**场景**：顾客提交订单后需要付款。

**操作**：选择支付方式 —— 微信支付（直接从微信扣款）或会员卡储值（用会员余额支付）。

**结果**：支付成功后，订单进入"待制作"状态，后厨开始做菜。

### 4. 订单状态实时查看

**场景**：顾客想知道菜做没做好。

**操作**：打开"我的订单"，可以看到订单进度：待支付 → 待制作 → 制作中 → 待上菜 → 已完成。

**结果**：后厨出餐时会有提醒，顾客知道什么时候可以吃饭，不用催服务员。

## 三、角色二：收银员 — POS 收银系统

收银员是餐厅的"前台大脑"，主要负责接单、收钱、管桌台。

### 1. 收银主界面（index.html）

**场景**：顾客来了，要安排座位、下单、结账。

**操作**：点击桌台 → 选菜品 → 确认订单 → 收款。

**结果**：订单自动传到后厨，桌台状态变为"就餐中"。

### 2. 桌台管理（tables.html）

**场景**：餐厅有多个桌台，需要知道哪些空、哪些有人、哪些预订了。

**操作**：在桌台图上可以看到每个桌台的状态（空闲 / 就餐中 / 预订），点击可以切换状态。

**结果**：服务员不会带客到有人的桌，预订的桌不会被占用。

### 3. 支付结算（payment.html）

**场景**：顾客吃完饭要结账。

**操作**：选择支付方式（微信、支付宝、现金、会员卡），输入金额，系统自动算找零。

**结果**：打印小票，桌台自动变为"待清台"，营业数据计入当日统计。

### 4. 后厨 KDS（kitchen.html）

**场景**：后厨需要知道做什么菜、按什么顺序做。

**操作**：厨师看到"待制作"的订单，点击"开始制作"；做好后点击"出餐叫号"。

**结果**：顾客小程序里会收到出餐提醒，服务员知道哪桌菜好了。

### 5. 菜品与配方（dishes.html）

**场景**：餐厅新上了一道菜，需要告诉系统这道菜用什么食材。

**操作**：添加菜品名称、价格，设置"BOM 配方"（比如西红柿炒蛋 = 西红柿 200g + 鸡蛋 2 个）。

**结果**：顾客点这道菜时，系统自动扣减对应食材的库存。

### 6. 食材库存（inventory.html）

**场景**：餐厅需要知道还剩多少食材，什么时候该补货。

**操作**：查看库存列表，低于安全库存的会标红提醒；还可以登记食材损耗（比如西红柿烂了）。

**结果**：不会出现"顾客点了菜但没食材"的尴尬情况。

### 7. 向美菜采购（purchase.html）

**场景**：库存不够了，要向美菜平台下单买食材。

**操作**：系统自动生成"采购建议"（根据销量和库存算出该买多少），确认后提交订单。

**结果**：美菜平台收到订单，供应商送货到店，库存自动增加。

### 8. 退单退款（refund.html）

**场景**：顾客不满意，要退款。

**操作**：选择订单，填写退款原因和金额，大额退款需要店长审批。

**结果**：顾客收到退款，系统记录退款原因，方便后续分析。

### 9. 营业日结（daily.html）— 含交接班

**场景**：收银员要下班了，需要把钱和工作交接给下一班。

**操作**：
1. 数现金（系统自动算出"应有现金"，人工数"实点现金"）
2. 核对交接事项（待处理的退款、待清台的桌、库存预警）
3. 确认日结并交接班

**结果**：本班数据冻结，下一班开始，每个人对自己当班的账负责。

### 10. 会员与营销（member.html）

**场景**：餐厅想做会员活动，吸引顾客回头。

**操作**：设置会员等级（普通/银卡/金卡），创建优惠券、积分规则。

**结果**：会员消费有优惠，积分可以兑换礼品，顾客更愿意来。

### 11. 营业报表（orders.html）

**场景**：老板想知道今天卖了多少钱、哪些菜卖得好。

**操作**：查看订单统计、菜品销量排行、支付方式占比。

**结果**：一目了然知道经营情况，方便做决策（比如多进什么食材、少进什么）。

## 四、角色三：后厨人员 — KDS 厨显系统

后厨人员只看一个页面：**后厨 KDS**（kitchen.html）。

### 核心流程

1. **接单**：看到新订单，点击"开始制作"，卡片移到"制作中"
2. **出餐**：菜做好了，点击"出餐叫号"，系统自动叫号提醒服务员
3. **催单**：超过 15 分钟未出餐的订单会自动标红闪烁，提醒优先处理

### 为什么需要 KDS

不用跑单、不用喊号，厨师盯着屏幕就能干活，效率更高。

## 五、角色四：老板 / 店长 — 管理后台

老板不用天天在店里，通过管理后台就能掌控全局。

### 1. 数据看板（admin/index.html）

**场景**：老板想快速了解今天的经营情况。

**操作**：打开看板，看到今日营业额、订单数、客单价、热销菜品等数据。

**结果**：一眼看清经营状况，不用翻报表。

### 2. 订单管理（admin/orders.html）

**场景**：有顾客投诉订单问题，需要查订单详情。

**操作**：搜索订单号，查看订单状态、支付信息、配送情况。

**结果**：快速定位问题，给顾客回复。

### 3. 商品管理（admin/products.html + categories.html）

**场景**：平台要上新商品，或者调整商品分类。

**操作**：添加商品信息、设置分类（蔬菜、肉类、粮油等）。

**结果**：餐厅在采购时能看到最新的商品列表。

### 4. 供应商管理（admin/suppliers.html + supplier-audit.html）

**场景**：有新供应商想入驻平台，需要审核。

**操作**：查看供应商资料，审核资质，通过后允许入驻。

**结果**：保证平台供应商的质量，餐厅采购更放心。

### 5. 库存管理（admin/inventory.html）

**场景**：平台仓库需要补货，或者处理临期商品。

**操作**：查看平台库存，处理库存预警、临期商品、滞销商品。

**结果**：保证平台有货可发，减少损耗。

### 6. 会员等级（admin/member-levels.html）

**场景**：想调整会员权益，比如金卡会员折扣更高。

**操作**：设置不同等级的会员权益（折扣、积分倍率、专属服务）。

**结果**：会员体系更完善，顾客粘性更高。

### 7. 权限设置（admin/permissions.html）

**场景**：不同员工看不同的页面，不能让收银员看到财务数据。

**操作**：设置角色（收银员、店长、老板），分配不同的页面访问权限。

**结果**：数据安全，各司其职。

## 六、角色五：供应商 — 供应商端

供应商在平台上卖货给餐厅。

### 1. 入驻申请（supplier/supplier-join.html）

**场景**：供应商想在美菜平台开店。

**操作**：填写企业信息、资质证明，提交审核。

**结果**：审核通过后，成为平台供应商，可以发布商品。

### 2. 商品发布（supplier/product-publish.html）

**场景**：供应商想上架新商品。

**操作**：填写商品信息（名称、规格、价格、图片），提交审核。

**结果**：审核通过后，商品出现在平台上，餐厅可以采购。

### 3. 报价管理（supplier/my-quotes.html）

**场景**：餐厅发来询价单，供应商需要报价。

**操作**：查看询价单，填写报价，提交。

**结果**：餐厅选择满意的报价，生成采购订单。

### 4. 订单处理（supplier/orders.html）

**场景**：餐厅下了采购订单，供应商需要发货。

**操作**：查看订单，确认备货，安排配送。

**结果**：餐厅收到货，库存增加。

## 七、哪些是自动的，哪些需要人做

### 自动完成（系统干）

| 功能 | 说明 |
|---|---|
| 库存扣减 | 顾客下单后，自动按 BOM 扣减食材库存 |
| 库存预警 | 库存低于安全线，自动标红提醒 |
| 采购建议 | 根据销量和库存，自动算出该买多少 |
| 交接事项 | 自动汇总待处理事项（退款、清台、库存） |
| 营业统计 | 自动计算营业额、订单数、客单价 |
| 微信对账 | 自动核对微信支付流水和 POS 记录 |
| 订单状态同步 | 后厨操作后，自动同步到顾客小程序 |

### 需要人做（人工干）

| 功能 | 说明 |
|---|---|
| 数现金 | 交接班时必须人工数钱，填到系统里 |
| 确认盘点 | 核对实点现金和应有现金的差异 |
| 清台 | 服务员看到桌空了，手动点"清台" |
| 食材盘点 | 定期盘点食材实际数量，调整系统库存 |
| 损耗登记 | 食材坏了、丢了，手动登记损耗 |
| 批退款 | 大额退款需要店长审核确认 |
| 审核商品/供应商 | 平台审核新商品和新供应商 |

## 八、常见问题解答

### Q1：顾客扫码后怎么知道自己坐哪桌？
A：二维码里包含桌号信息，扫码后系统自动绑定，下单时会自动关联桌号。

### Q2：库存不够了怎么办？
A：系统会自动提醒（标红），并生成采购建议，收银员确认后就可以向美菜下单。

### Q3：交接班时钱对不上怎么办？
A：系统会算出"差异"，需要收银员备注原因（比如顾客跑单、找零错误），确认后才能交班。

### Q4：后厨怎么知道做哪桌的菜？
A：KDS 屏幕上会显示桌号、菜品、下单时间，厨师按顺序做就行。

### Q5：会员优惠怎么用？
A：顾客登录小程序后，系统自动识别会员等级，结算时自动享受折扣或积分。

## 九、快速体验路径

如果想快速体验系统，可以按这个顺序：

1. **顾客视角**：打开小程序 → 扫码绑桌 → 点餐 → 支付 → 看订单状态
2. **收银员视角**：POS 收银主界面 → 接单 → 看后厨 KDS → 结账
3. **库存视角**：食材库存 → 看预警 → 生成采购建议 → 下单
4. **管理视角**：营业日结 → 看交接班 → 看营业报表
