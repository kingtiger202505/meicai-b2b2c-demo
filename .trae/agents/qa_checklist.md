# 全局 QA 验证与资金安全审计规范

本规范用于对整个系统的客户端（小程序）、POS端、管理后台（Admin）和平台端（Platform）进行全链路功能与资金安全性验证。

---

## 一、 核心资金安全与防刷测试 (Critical - 金融级保障)

### 1. 钱包与余额安全 (RPC 层面防篡改)
- [ ] **高并发余额扣减 (并发测试)**:
  - 场景: 顾客在同一订单上短时间内多次连续点击“余额支付”。
  - 预期: 必须触发数据库锁或幂等标识校验，仅成功扣除一次，返回 `idempotent: true`。
- [ ] **负余额拦截 (溢出测试)**:
  - 场景: 故意构造负数金额充值，或者在余额为 `0` 时调用 `pay_with_balance`。
  - 预期: 后端 RPC 直接报错拦截，不允许余额字段为负数（`balance >= 0` 约束）。
- [ ] **退款余额回滚一致性**:
  - 场景: 订单被取消或发生退款。
  - 预期: 触发 `refund_order_by_id` 后，不仅订单状态变为已退款，原支付余额必须原路返还到对应会员的 `balance` 中，且写入一条 `refund` 流水。

### 2. 营销券核销防刷
- [ ] **优惠券一次性校验**:
  - 场景: 下单选择优惠券并支付。
  - 预期: 券状态立即标记为 `used`，再次携带该 `coupon_id` 下单或核销返回 `coupon_already_used`。
- [ ] **优惠券满减门槛校验**:
  - 场景: 订单金额低于优惠券 `threshold` 时尝试使用该券。
  - 预期: 后端 RPC 校验报错，不予抵扣。

## 二、 全链路功能模块回归测试用例 (Regressions)

### 1. 顾客端小程序 (Miniapp)
- [ ] **登录与手机关联**:
  - 微信静默登录获取 openid → 绑定手机号快捷解密回填 → 同步更新并生成后端统一 Member。
- [ ] **充值赠送展示**:
  - 充值选择 100 额外得 20，200 额外得 40，多充多送。
- [ ] **优惠券包**:
  - 进入“我的优惠券”列表，确保数据来源于后端 `list_my_coupons`。

### 2. 收银与门店端 (POS App)
- [ ] **订单接单与完结**:
  - 顾客小程序下单 → POS端实时收到提醒 → 点击接单 → 制作完成点击“完结”归档。
- [ ] **异常退款处理**:
  - POS端点击订单“退款”或“取消”，验证关联的优惠券包/余额发生回滚。
- [ ] **交班与日结**:
  - 验证交班报表对账，实收现金、微信号、余额扣减各账目对齐。

### 3. 商户管理端 (Admin App)
- [ ] **菜品与分类管理**:
  - 新增/上下架菜品，关联修改在小程序端实时更新。
- [ ] **营销规则下发**:
  - 配置“新客礼包包（满100减20）”，新用户注册自动到账券。

### 4. 平台端 (Platform App)
- [ ] **多商户入驻审计**:
  - 平台对申请加盟的商家进行资质初审与商户号绑定。
